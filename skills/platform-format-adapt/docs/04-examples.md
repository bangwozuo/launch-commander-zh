# 使用示例

以下示例均为按 prompt.txt 方法论产出的真实适配稿（无占位符），展示四种典型场景。

---

## 示例 1：一稿三平台（完整走查）

**输入**：见 `examples/input.json`（ClipMate 主稿 → X/V2EX/即刻）。

**输出**（全文见 examples/output.md）：

| 平台 | 关键改动 |
|---|---|
| X | 首行换成「丢第 7 个 API key」故事；链接移回复（首条带链接降权）；271/280 字符 |
| V2EX | 补「为什么做」段落 + GitHub 链接；结尾以具体交互问题求建议（带来真讨论） |
| 即刻 | 加「一个人两年 nights and weekends」花絮（即刻吃花絮）；3:4 竖图 ×3 |

证据零件「0.3s / 10 万条实测 / $8」在三版中一字未删。

---

## 示例 2：X 超长降字（删减顺序纪律）

**输入**：主稿 400 字符（含 2 个形容词、1 段背景、3 个卖点、1 组数据）。

**输出**（压缩到 278 字符的删减轨迹）：

| 轮 | 动作 | 余量 |
|---|---|---|
| 1 | 删形容词「amazing / super clean」 | -38 |
| 2 | 背景从 2 句压成 1 句 | -60 |
| 3 | 次要卖点（深色模式支持）删除 | -24 |
| — | 钩子 / 核心卖点 / 「10 万条实测」数据：**未动** | 278 ✅ |

**要点**：删减按「形容词→背景→次要卖点」顺序，证据与钩子永不删。

## 示例 3：Reddit 合规改写（利益相关披露）

**输入**：用户要求在 r/SideProject 发帖但「别写 I made this，显得像广告」。

**输出**：**拒绝隐瞒**——Reddit 不披露开发者身份被识破 = 版封 + 截图挂人，风险远大于
流量收益。改写方案：

> I've been building a clipboard manager for Windows for two years as a side project
> (I made this — disclosure per the rules). Here's what I learned about local-first
> storage along the way: …

把「广告帖」改写成「经验分享帖 + 披露」，既合规又更符合该版气质。

---

## 示例 4：规格存疑标注（不猜）

**输入**：用户要求适配「知乎」专栏，但规格表没有知乎条目。

**输出**：在核对表标注「知乎：规格未收录，需核对官方最新规范后再适配」，同时给出
可确定的通用建议（首行钩子/图文分离/不做标题党），**不编造字数上限**。
