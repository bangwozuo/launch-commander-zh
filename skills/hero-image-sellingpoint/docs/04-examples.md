# 使用示例

以下示例的输入均为**真实可跑数据**，脚本输出由 `scripts/sellingpoint_score.py` 实跑产生
（Python 3.13，退出码 0）。

---

## 示例 1：五个功能选四个（可演示性一票否决）

**输入**：见 `examples/input.json`（ClipMate 五功能，含一个不可演示的加密同步）。

**输出**（实跑）：

| 排名 | 卖点 | 得分 | 入选 | 关键判定 |
|---|---|---|---|---|
| 1 | 全局历史搜索 | 90.0 | ✅ | speed 型 GIF，0.3 秒找回演示 |
| 2 | 截图 OCR 取字 | 80.0 | ✅ | showcase 型，差异化 4 分 |
| 3 | 代码片段纯粘贴 | 70.0 | ✅ | before_after 型，程序员痛点 |
| 4 | 低内存占用 | 60.0 | ✅ | 任务管理器对照演示 |
| 5 | 端到端加密同步 | 20.0 | ❌ | demoable=0 一票否决，无画面 |

**要点**：加密同步是开发者自己最得意的功能，但「无画面可演示 + 受众宽度 2」把它
挡在首图外——这正是评分规则要拦的错误。

## 示例 2：TOP2 分差过小（主卖点不突出）

**输入**：

```json
{
  "product": "TabTidy",
  "features": [
    {"name": "一键收纳所有标签页", "description": "点击即收纳", "demoable": 1, "wow": 4, "breadth": 5, "uniqueness": 2},
    {"name": "收纳历史恢复", "description": "随时找回关掉的标签组", "demoable": 1, "wow": 4, "breadth": 4, "uniqueness": 2}
  ]
}
```

**输出**（实跑口径）：两卖点分差 <5，触发检查「TOP2 得分差 <5 分——主卖点不突出，
首图主视觉会犹豫；用用户访谈或竞品对比补判」。

**处置**：拿两个卖点各做一版首图，用 PH 预热帖 A/B 或者找 5 个目标用户盲选。

## 示例 3：可演示卖点不足（入选 <3）

**输入**：

```json
{
  "product": "SecureDrop",
  "features": [
    {"name": "零知识加密", "description": "服务端不可见内容", "demoable": 0, "wow": 3, "breadth": 3, "uniqueness": 4},
    {"name": "审计日志", "description": "所有访问留痕", "demoable": 0, "wow": 2, "breadth": 2, "uniqueness": 3}
  ]
}
```

**输出**（实跑口径）：入选 0 个，触发检查「入选卖点仅 0 个（<3 个）——可演示卖点
不足：检查是否把强功能标了 demoable=0，或功能本身需要补录屏」。

**处置**：把「零知识加密」改造成可演示形态——演示「服务端视角看到的全是密文」
（before/after 型），demoable 翻转后重跑评分。

---

## 示例 4：数量超限（>5 个入选）

**输入**：8 个功能全部 demoable=1 且高分。

**输出**（实跑口径）：触发检查「入选超过 5 个——首图只讲 3-5 个卖点，超出部分移到
详情页」。取前 5，第 6-8 名进详情页「完整功能」区。
