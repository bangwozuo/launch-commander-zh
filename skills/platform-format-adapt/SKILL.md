# 平台格式适配

把主稿改写成各平台的**原生帖子**——重组结构、换装证据、母语重写，不是删减凑字数。
adapted 的标准：看不出是从别处复制来的。

不做的事：不发布、不做图、不虚构平台规格（拿不准标「需核对官方」）。

## 能力描述

1. **平台规格表**：7 个平台的标题/正文长度、图片规格、发布时点、结构要求硬约束，
   逐项核对输出核对表
2. **五步适配法**：拆主稿成五零件（钩子/卖点/证据/召唤/花絮）→ 定平台策略 →
   重组零件 → 母语重写 → 逐项核对
3. **时点内建**：PH 00:01 PT、X 9AM/8PM EST 双峰、Reddit 工作日 8-10AM EST、
   V2EX 上午 10 点、即刻/小红书/公众号晚 8-10 点
4. **禁忌扫描**：X 首条链接降权、Reddit 必须披露 I made this、V2EX 标题党、
   小红书导流敏感词
5. **字数换算纪律**：删减顺序=形容词→背景→次要卖点；钩子/核心卖点/证据永不删

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `content` | string | ✅ | 主稿全文（PH 版或产品说明） |
| `platforms` | array | ✅ | 目标平台：ProductHunt / X / Reddit / V2EX / 即刻 / 小红书 / 微博 / 公众号 |
| `launch_date` | string | ⬜ | 发布日（倒排各平台时点） |
| `notes` | string | ⬜ | 特殊要求 |

## 输出规格

| 件 | 说明 |
|---|---|
| `adapted` | 各平台版本全文 + 图说明 + 发布时点 |
| `checklist` | 逐平台核对表（长度/图规格/禁忌/口径一致） |
| `change_log` | 改动说明（主稿→各版实质改动与理由） |

## 使用步骤

### 方式一：纯提示词

1. 把 `prompt.txt` 全部内容粘贴为系统提示词
2. 提供主稿 + 目标平台 + 发布日
3. 得到适配总览 + 各平台全文 + 逐平台核对表 + 改动说明

### 在流程中的位置

- 主稿写作 → `producthunt-copy`；卖点 → `hero-image-sellingpoint`
- 本技能产出各平台版本 → 中英版本语感终审走 `bilingual-switch` 口径核对
- 产出版本进入 `multi-platform-copy-adapt-flow` 与 `publish-calendar-flow` 排期

## 边界（不做的事）

- ❌ 不做一稿多发式复制粘贴——每个平台重组结构
- ❌ 不删证据链——主稿数据/背书删掉 = 适配稿变空话
- ❌ 不虚构平台规格——拿不准标「需核对官方」，不猜
- ❌ 不帮用户在 Reddit 隐瞒利益相关（I made this 必须写）
- ❌ 不用导流敏感词替代正规链接

## 调用示例

**输入**（`examples/input.json`，节选）：

```json
{
  "content": "ClipMate 主稿（PH 版）：Your clipboard, finally searchable. …",
  "platforms": ["X", "V2EX", "即刻"],
  "notes": "中文社区需要开发背景花絮；X 需 thread 两条"
}
```

**输出**（见 examples/output.md）：X thread 首条 271 字符（链接移回复位防降权）、
V2EX 版补「为什么做」故事并以具体技术问题收尾、即刻版加两年独立开发花絮；
核对表三项全过，「0.3s/10 万条实测」证据在各版本一字未删。

## 合规声明

- 输出标注「AI 生成内容」，各平台版本人工确认后发布
- 价格、数字、承诺在各平台版本中一字不差（口径漂移 = 信任事故）
- 各平台 AI 内容标识按现行要求执行；平台规则以官方最新为准
