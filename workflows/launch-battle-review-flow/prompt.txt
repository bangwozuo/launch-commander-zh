# 发布战报复盘流程（launch-battle-review-flow）

> 触发：事件，T+1 早上（战报）+ T+7（留存复盘）
> 产出：达标判定 + 平台结构 + 评论情绪分布 + 流量-情绪交叉观察 + 值守执行摘要
> 价值：沉淀可复用的发布资产；「达标没有、问题在哪层」有数据答案而不是感觉

# 流程目标

发布日的两份原始记录——**各平台指标**和**评论流**——通常各看各的：数据在后台、
评论在脑子里。本流程把它们合并成一份复盘包：五指标达标判定（battle-report-generate）
+ 情绪分布与风险统计（comment-emotion-detect）+ **流量-情绪交叉观察**（本流程合并层）
+ 值守 SLA 执行摘要。深度归因与行动建议由模型按 prompt 撰写（≤3 条），
脚本不越权写结论。

# 步骤明细（每步含输入/处理/输出/失败处理）

## 步骤 1：五指标战报

| 项 | 内容 |
|---|---|
| 技能 | `battle-report-generate`（scripts/battle_report.py） |
| 输入 | battle 段：targets（五指标目标）+ platforms（各平台 pv/signups/stars/waitlist/mentions）+ hourly_pv（可选） |
| 处理 | 达标三档判定（≥100%/70-100%/<70%）+ 平台占比与转化率 + 规则式归因提示（漏斗定位） |
| 输出 | out/battle_report.json + out/发布战报.xlsx + 两张 PNG |
| 失败处理 | 退出码 ≠0 → 中止打印 stderr；targets 未设 → 判定降级为「未设目标」 |

## 步骤 2：评论情绪统计

| 项 | 内容 |
|---|---|
| 技能 | `comment-emotion-detect`（scripts/emotion_scan.py） |
| 输入 | comments 段：发布日评论流（采样或全量，标注平台） |
| 处理 | 五类情绪 + 六类风险 + P0-P4 排队；按平台聚合风险/负面分布 |
| 输出 | out/emotion_scan.json + out/评论分类清单.xlsx + out/情绪分布.png |
| 失败处理 | 评论流为空 → 标「发布日 0 评论」不阻断战报段 |

## 步骤 3：复盘合并（内置）

| 项 | 内容 |
|---|---|
| 输入 | 步骤 1/2 产物 + duty_log（值守记录：P0/P1 处理时长、回复条数） |
| 处理 | 逐平台交叉：PV 占比 × 该平台风险/负面评论数 → 交叉观察（「流量主力且有风险评论——优先清该平台风险」等）；样本 <3 不下情绪结论；值守 SLA 摘要（无记录则标「建议下次记录」） |
| 输出 | out/复盘报告.xlsx（复盘要点 + 汇总）+ review_result.json |
| 失败处理 | 指标缺失但评论在 → 只出情绪复盘标注「补数据后复跑」；两者都缺 → 退出码 2 |

# 量化规则（判定不看感觉）

- 达标三档沿用战报口径（100%/70%），整体判定三档
- 交叉观察规则：PV 占比 ≥50% 的平台若风险评论 >0 → 「流量主力且有风险——优先清风险」；
  风险=0 → 「守住响应节奏」；评论样本 <3 → 「样本少，情绪结论不下」
- 值守 SLA：P0 30 分钟内处理率（p0_within_30min/p0_total）——发布日响应速度进
  PH 排名算法，这是复盘里唯一衡量「执行」而非「结果」的行
- 行动建议 ≤3 条，每条必须挂一个数据点（排名/转化率/风险数），由模型撰写、人工确认

# 失败模式（编排层特有）

- **评论只有好评截图**：存档偏差——只截好玩的，风险评论没进样本，情绪分布虚高；
  采样须覆盖 P0/P1 全量 + 其余随机
- **两套数据时间窗不齐**：PV 到 T+1 早 9 点、评论到 T+1 晚 8 点——交叉时标注
  各自窗口，不硬对齐
- **归因越权**：脚本只出「漏斗层定位」提示，「高光/失误/建议」若由脚本编造
  就成了没有证据的叙事——深度归因必须模型+人工
- **值守记录缺失**：P0 处理时长没人记 → SLA 行标「未记录」，T+0 值守流程
  （daily-comment-duty-flow）的 duty_log 字段就是为这个准备的

# 输出格式（复盘报告）

```markdown
## 复盘要点（流量 × 情绪交叉）

| 平台 | PV | PV占比 | 注册 | 评论样本 | 风险/负面 | 交叉观察 |
|---|---|---|---|---|---|---|

## 汇总

| 项 | 内容 |
|---|---|
| 整体判定 | ✅/🟡/🔴（达标 n/m） |
| PV→注册转化率 | … |
| 值守执行 | P0 30 分钟内 n/n |
| 深度归因与行动建议 | （模型撰写 ≤3 条，人工确认） |
```

# 编排规则

- DAG 节点 = 本仓真实技能 slug：`battle-report-generate`（战报）→
  `comment-emotion-detect`（情绪）→ 内置合并（交叉观察 + SLA 摘要）
- 步骤间经 JSON 衔接（battle_report.json / emotion_scan.json → review_result.json）
- 上游数据来源：指标由用户提供（后台导出），评论由 daily-comment-duty-flow 积累
- 模型介入点：深度归因、高光提炼、行动建议（≤3 条）；复盘结论人工确认后归档

# 合规

- 输出标注「AI 生成内容」；复盘含转化率等商业敏感项，对外分享前人工脱敏
- 评论样本属用户数据：复盘包内部使用，不外发；好评引用须获授权
- 不引用无授权第三方/竞品数据；单日数据不外推长期结论
