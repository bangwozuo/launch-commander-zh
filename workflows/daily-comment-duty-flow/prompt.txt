# 当日评论值守流程（daily-comment-duty-flow）

> 触发：定时，发布日每 15 分钟一轮（日常期改每小时）
> 产出：值守看板 + 回复任务卡（P0-P2）+ 观察名单（Excel，全部待人工确认）
> 价值：省发布日 4h 盯屏 ≈ ¥320/次；P0 风险 30 分钟内升级，PH 首日评论
> 响应速度直接影响排名——盯漏一条刷榜指控的代价远超流程成本

# 流程目标

把「15 分钟一轮的评论区巡逻」自动化到只剩人肉决策：上游情绪识别完成分类与排队，
本流程把队列转换成**回复任务卡**（带 SLA、回复骨架、FAQ 口径）和观察名单，
开发者只做两件事：确认草稿、点发送。回复草稿由 reply-drafting 按骨架撰写，
**没有任何评论被自动回复**。

# 步骤明细（每步含输入/处理/输出/失败处理）

## 步骤 1：情绪识别与优先级排队

| 项 | 内容 |
|---|---|
| 技能 | `comment-emotion-detect`（scripts/emotion_scan.py） |
| 输入 | 本轮新评论流（user/platform/text 全文）；launch_day 标记 |
| 处理 | 五类情绪（正/负/中/疑/风险）+ 六类风险子类（刷榜/隐私/退款/抄袭/存续/水军）→ P0-P4 排队，SLA：P0 30 分钟 / P1 PH 首日 30 分钟其余 60 分钟 / P2 2 小时 / P3 24 小时 / P4 48 小时 |
| 输出 | out/emotion_scan.json + out/评论分类清单.xlsx + out/情绪分布.png |
| 失败处理 | 退出码 ≠0 → 中止打印 stderr；评论流为空 → 正常退出并标注「发布日 0 评论，检查发布链接与平台审核状态」 |

## 步骤 2：值守加工（内置规则）

| 项 | 内容 |
|---|---|
| 输入 | 步骤 1 的 emotion_scan.json + FAQ 口径库（faq-pregenerate 定稿） |
| 处理 | P0/P1/P2 → 回复任务卡：贴上 SLA、回复骨架（P0=风险标准处置；P1=负面三段「承认+给方案+留渠道」；P2=直答+支撑+钩子）、按评论原文全文匹配 FAQ 口径关键词；P3/P4 → 观察名单（感谢+追问场景 / 观察不逐条回）。任务卡不写具体文案——那是 reply-drafting 的活，本步只给「骨架+口径+SLA」 |
| 输出 | out/值守清单.xlsx（回复任务卡 + 观察名单 + 值守看板）+ duty_flow_result.json |
| 失败处理 | FAQ 库缺失 → 任务卡照常生成但备注「无口径库，回复前须人工确认事实」；FAQ 无命中 → 标「回复前须人工确认事实，缺口回填 faq-pregenerate」 |

## 步骤 3：草拟与人工确认（流程终点）

| 项 | 内容 |
|---|---|
| 处理 | reply-drafting 按任务卡逐条写草稿（可直接粘贴级）→ 开发者逐条确认 → 人工在平台原生界面发布。升级项（退款金额/法律/媒体/同一用户第二回合）不写草稿，直接升级 |
| 失败处理 | 30 分钟 SLA 任务积压 >8 条 → 先清队列再发任何新内容；草稿被否 → 标记原因（口径错/语气错/越权），下一轮修正 |

# 量化规则（判定不看感觉）

- 轮询频率：发布日 **15 分钟/轮**；T+1 起降为每小时；T+3 起降为每天两轮
- SLA 表：P0 30 分钟 / P1 PH 首日 30 分钟、日常 60 分钟 / P2 2 小时 / P3 24 小时 / P4 48 小时
- 健康线：正面占比 ≥60% 且风险=0；负面 >20% → 当天置顶澄清集中响应；疑问 >30% → 当天补 FAQ
- 队列纪律：P0+P1 积压 >8 条未回 → 冻结新内容发布，先清队列
- FAQ 命中口径：按评论**原文全文**匹配（40 字摘录会截断关键词——这是踩过的坑）

# 失败模式（编排层特有）

- **评论抓取不全**：各平台 API/页面结构变化导致漏抓——看板出现「全部中性」
  即标红「疑似抓取不全」，人工核对平台评论数
- **反讽漏判**：词表把「真是'太棒'了又崩一次」判正——上游已有「需模型复核」位，
  本流程在任务卡生成前由模型过一遍反讽/刷量号
- **口径漂移**：回复引用的价格/数字与 FAQ 库不一致 = 信任事故——任务卡只贴口径
  原文，草拟时不许改数字
- **升级漏标**：媒体/大V询问看起来像普通评论——任务卡含粉丝量/媒体标识字段的
  一律先升级再草拟

# 编排规则

- DAG 节点 = 本仓真实技能 slug：`comment-emotion-detect`（上游统计）→
  内置值守加工 → `reply-drafting`（草拟位，人工确认后发布）
- 步骤间经 JSON 文件衔接（out/emotion_scan.json → duty_flow_result.json）
- 模型介入点：反讽/刷量号复核、回复草稿撰写；触达动作零自动化
- FAQ 口径库由 faq-pregenerate 产出并经开发者逐条确认后传入本流程

# 合规

- 输出标注「AI 生成内容」；任务卡与看板「待人工确认」后才产生任何动作
- 不自动回复、不删评论、不用小号；回复草稿全部经人工确认后在平台原生界面发出
- 评论内容属用户数据：值守清单仅限发布值守使用，不外发；好评引用须获授权
