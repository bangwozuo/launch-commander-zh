# 发布日历排期流程（publish-calendar-flow）

> 触发：人工，T-3 天启动（素材定稿前需要先有日历）
> 产出：倒排发布日历（T-7→T+7）+ T-0 分时区时点表（本地换算）+ T-1 十项检查清单
> 价值：省 2h/次 ≈ ¥160/次；更重要的是把「发布日几点干什么」从记忆变成日程，
> 时区算错/忘设闹钟这类低级事故归零

# 流程目标

以发布日 T0 为锚，用 publish-schedule 的 SOP 规则倒排出**可执行的日历**：
每个节点带人工确认点，每个平台时点换算成开发者本地时间，PH 黄金窗口自动保护。
产出直接可导入日历工具（只读订阅提醒），发布动作零自动化。

# 步骤明细（每步含输入/处理/输出/失败处理）

## 步骤 1：倒排日历生成（SOP 规则内置）

| 项 | 内容 |
|---|---|
| 输入 | launch_date（ISO 日期）、product |
| 处理 | 以 T0 为锚倒排七节点：T-7 预热（waitlist/预告帖+素材三件套）→ T-3 定稿（文案包+FAQ≥15条+多平台版）→ T-1 全平台预检（十项清单）→ T-0 分时区发布 → T+1 战报 → T+7 复盘；每节点带人工确认点 |
| 输出 | out/发布日历.xlsx「倒排日历」sheet + publish_calendar.json.calendar |
| 失败处理 | launch_date 缺失/非法 → 退出码 2 打印修复提示，**不编造日期** |

## 步骤 2：T-0 分时区时点表（本地换算 + 黄金窗口保护）

| 项 | 内容 |
|---|---|
| 输入 | platforms、local_utc_offset（开发者时区） |
| 处理 | 各平台时点（PH 00:01 PT / X 9AM+8PM EST 双峰 / Reddit 工作日 8-10AM EST / V2EX 上午10点 / 即刻等晚 8-10 点 CST）→ 按时区换算为本地日期时间；标跨日；检查是否落入 PH 黄金窗口（00:01-02:00 PT 的本地区间）冲突；发布日为周末时 Reddit 顺延周一 |
| 输出 | 「T0时点表」sheet + 发布日T0时间轴.png |
| 失败处理 | 平台不在支持列表 → 保留并标「待人工补充时点」；黄金窗口冲突 → 列出冲突项并建议移出 |

## 步骤 3：T-1 检查清单与升降级规则（SOP 判断层）

| 项 | 内容 |
|---|---|
| 输入 | 步骤 1/2 产物 |
| 处理 | 十项检查清单落表（第 1/6/7 项为红线：链接死链、价格不一致、账号异常）；预置升降级规则——升级（waitlist 超预期 50%+ 可提前中文平台，PH 不动）、降级（红线未过延后 24h）、中止（P0 bug 先修后发） |
| 输出 | 「T1检查清单」sheet（红线行标红）+「黄金窗口冲突」sheet |
| 失败处理 | 清单结果由人工 T-1 当天回填；本流程不代打勾、不代发布 |

# 量化规则（判定不看感觉）

- 时点换算精度到分钟；跨日事件显式标注（如 PT 午夜 = 本地次日下午）
- PH 黄金窗口 = 00:01-02:00 PT 的本地时段，窗口内 ±120 分钟不排其他平台动作
- Reddit 仅工作日发布（周一至周五），周末自动顺延下一个周一
- T-3 硬门槛：FAQ 口径库 ≥15 条才允许进入 T-1；不达标 → T-3 延期而不是砍 FAQ
- 闹钟规则：PH 上线时刻前 30/10/0 分钟各一个，共 3 个

# 失败模式（编排层特有）

- **时区夏令时错位**：PT 在 11 月切回 UTC-8、3 月切回 UTC-7——跨夏令时切换日的
  发布必须人工复核换算（脚本按基线偏移计算并标注「跨夏令时需复核」场景）
- **日历导入成可写**：日历工具若授予写权限，自动改期会悄悄打乱节点——只导出
  只读订阅
- **周末发布冲动**：Reddit 周末流量仅为工作日的 30-40%，脚本能拦（顺延规则），
  但人容易忘
- **确认点批处理**：T-3 的 FAQ 口径逐条确认最容易被「都差不多」糊弄过去——
  确认点在日历里是独立动作，不允许合并勾选

# 输出格式（发布日历）

```markdown
## 倒排日历

| 节点 | 日期 | 星期 | 动作 | 人工确认点 | 状态 |
|---|---|---|---|---|---|

## T-0 时点表（本地换算）

| 平台 | 本地日期 | 本地时间 | 动作 | 备注 | 状态 |
|---|---|---|---|---|---|

## T-1 检查清单

| # | 检查项 | 红线 | 结果 | 备注 |
|---|---|---|---|---|

## 黄金窗口冲突

| 冲突 |
|---|
```

# 编排规则

- DAG 节点 = `publish-schedule`（SOP 规则来源，本流程将其规则内置执行）
- 与兄弟流程衔接：T-0 当天值守交给 `daily-comment-duty-flow`；T+1 交给
  `launch-battle-review-flow`（经 out/publish_calendar.json 传递发布日锚点）
- 发布动作零自动化：脚本产出的是「谁、几点、干什么」的表，不是发布器

# 合规

- 输出标注「AI 生成内容」；日历与清单仅提醒与检查，发布动作人工执行
- 不用 incentivized 手段凑首发势能；Reddit 披露利益相关；中文平台 AIGC 标识按现行要求
- 时点为经验基线，以平台官方最新规则为准
