# 发布素材包生成流程（launch-kit-generate-flow）

> 触发：人工，T-7 天启动（发布倒排的起点）
> 产出：卖点评分入选清单 + PH 文案包硬约束校验 + FAQ 覆盖度校验（Excel + JSON）
> 价值：省 6-8h/次 ≈ ¥500-640/次；把「素材齐没齐」从感觉变成可打勾的硬约束——
> tagline 超长、价格打架这类事故在 T-7 被拦住，而不是 T-1 深夜

# 流程目标

产品信息进，**可直接上传的素材包**出：三件套 = PH 文案包（producthunt-copy）+
首图卖点与 GIF 方案（hero-image-sellingpoint）+ FAQ 口径库（faq-pregenerate）。
本流程编排三件套的生成顺序与**硬约束校验**——文案由模型写，尺寸、字数、价格
一致性由脚本查，人不该在 T-3 深夜数像素。

# 步骤明细（每步含输入/处理/输出/失败处理）

## 步骤 1：卖点评分与首图方案

| 项 | 内容 |
|---|---|
| 技能 | `hero-image-sellingpoint`（scripts/sellingpoint_score.py） |
| 输入 | 功能列表（name/description/demoable/wow/breadth/uniqueness，4-5 分须挂证据） |
| 处理 | 四维加权（演示性 35%+冲击力 25%+受众宽度 25%+差异化 15%）→ 得分排序 → 入选规则（≥60 分且可演示，取前 5）→ GIF 分镜骨架 |
| 输出 | out/sellingpoint.json + out/卖点评分清单.xlsx + out/卖点评分对比.png |
| 失败处理 | 退出码 ≠0 → 中止；入选 <3 → 列「可演示卖点不足」待办（先补录屏素材再重评，不硬凑弱卖点） |

## 步骤 2：PH 文案包硬约束校验（内置）

| 项 | 内容 |
|---|---|
| 输入 | ph_copy 字段：tagline / gallery_count / gallery_size / demo_video_seconds / price_pages |
| 处理 | 逐项硬校验：tagline ≤60 字符且无句号（超长→重写不是截断）；gallery 5 张 1270×760；demo 视频 ≤60s；**价格三处一致**（官网/PH/README 逐字比对，不一致=红线） |
| 输出 | 「硬约束校验」sheet 逐项 ✅/❌/缺失 |
| 失败处理 | 红线未过（价格不一致）→ 整体判定「不可进入 T-1」；非红线项缺失 → 标待办不阻断 |

## 步骤 3：FAQ 覆盖度校验（内置）

| 项 | 内容 |
|---|---|
| 输入 | faq_total / faq_categories（六类条数） |
| 处理 | 总量 ≥15 条；六类质疑（价值/价格/隐私/可持续/平台/边界）每类 ≥2；缺口列清单 |
| 输出 | 校验项 + FAQ 缺口清单（进汇总） |
| 失败处理 | 覆盖不足 → ⚠️ 非红线，T-3 前补齐即可；但**没有 FAQ 定稿不允许过 T-1**（该规则在 publish-calendar-flow 执行） |

# 量化规则（判定不看感觉）

- tagline ≤60 字符、gallery 5 张 1270×760、demo 视频 ≤60s——PH 机制的硬数字
- 价格一致性：**逐字比对**（「$8/mo」vs「$8/月」也算不一致——对外口径必须统一）
- 卖点入选：得分 ≥60 且 demoable=1，取前 5；首图主视觉 = TOP1
- FAQ：总量 ≥15、六类每类 ≥2、攻击性问题占比 ≥1/3（由 faq-pregenerate 保证，本步查数量）
- 产出时限：三件套 T-7 启动、T-3 定稿——每件素材都必须在 T-1 前过完本流程校验

# 失败模式（编排层特有）

- **文案先写、卖点后定**：顺序颠倒会导致文案与首图各说各话——本流程强制卖点
  评分先行，PH 文案包以 TOP 卖点为纲
- **校验绕过**：模型自信「差不多 60 字符」——字数/尺寸校验只认脚本结果，
  模型不得自判通过
- **价格悄悄改**：定价改动只更新了官网忘了 README——逐字比对就是为这个准备的
- **FAQ 拿模板凑数**：15 条里 12 条是「如何下载」类温吞问题——数量达标但攻击性
  不足，T-0 照样被抓瞎；本流程把缺口清单显式列出供人工审视质量

# 输出格式（素材包校验清单）

```markdown
## 硬约束校验

| 件 | 标准 | 结果 | 说明 | 红线 |
|---|---|---|---|---|

## 入选卖点（TOP1 = 首图主视觉）

| 排名 | 功能 | 得分 | GIF 类型 | 入选 |
|---|---|---|---|---|

## 汇总

| 项 | 内容 |
|---|---|
| 整体判定 | ✅ 可进入 T-1 / ⚠️ 补齐非红线项 / ❌ 红线未过 |
```

# 编排规则

- DAG 节点 = 本仓真实技能 slug：`hero-image-sellingpoint`（脚本）→ 内置校验 ×2；
  `producthunt-copy` 与 `faq-pregenerate` 为文案/口径生成位（模型执行，产出回填
  ph_copy 与 faq 字段后过校验）
- 步骤间经 JSON 衔接（sellingpoint.json → kit_result.json）
- 校验结果对接 `publish-calendar-flow` 的 T-1 清单（本流程全绿是 T-1 的前提）

# 合规

- 输出标注「AI 生成内容」；素材上传前人工终审
- 文案不编造数据、不含 incentivized 投票话术、不攻击竞品（各生成技能负责，本流程校验抽查）
- 价格与支付链接以官网为准；对外口径三处统一
