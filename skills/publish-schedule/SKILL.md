# 发布排期

把「发布日几点干什么」用倒排时间轴钉死：发布日历 + T-1 检查清单 + 分时区时点表 +
升降级规则。让发布日不靠记忆和运气。

不做的事：不写文案、不做素材、不自动发布。

## 元信息

| 字段 | 值 |
|------|-----|
| ID | `de_dev_02_sk06` |
| 类型 | **`atomic`（T4 调度型 SOP）** |
| 所属员工 | 发布指挥官 |
| 能力族 | 调度编排型 · 发布日历与检查清单 |
| 复杂度 | `S` |
| 阶段 | `P0` |
| 复用度 | 高（每次发布/版本更新复用） |
| 资产形态 | SOP 提示词（无脚本、无连接器依赖） |

## 能力描述（SOP 四件）

1. **倒排日历**：T-7 预热 → T-3 素材定稿 → T-1 全平台预检 → T-0 分时区发布 →
   T+1 战报 → T+7 复盘，每节点带人工确认点
2. **T-1 十项检查清单**：链接可点 / PH gallery 1270×760 / X 16:9 / tagline ≤60 字符 /
   demo 视频 ≤60s / 价格三页一致 / 账号状态（V2EX 注册 >30 天）/ FAQ ≥15 条 /
   时区闹钟 / UTM 埋点
3. **T-0 时点表**：PH 00:01 PT（抢当日榜 + 30 分钟内 maker comment）、X 9AM/8PM EST
   双峰、Reddit 工作日 8-10AM EST、V2EX 上午 10 点、中文社区晚 8-10 点；
   本地时间自动换算并设 3 个闹钟
4. **升降级规则**：升级（waitlist 超预期 50%+ 可提前中文平台，PH 不动）/
   降级（T-1 红线未过延后 24h，不带病上线）/ 中止（P0 bug 先修后发）

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `launch_date` | string | ✅ | 发布日 T-0（星期几影响 Reddit 工作日规则） |
| `timezone_local` | string | ⬜ | 开发者本地时区（00:01 PT 换算用） |
| `platforms` | array | ⬜ | 目标平台 |
| `waitlist_size` | integer | ⬜ | 当前 waitlist 人数（升降级阈值用） |
| `product` / `notes` | string | ⬜ | 产品名 / 特殊约束 |

## 输出规格

| 件 | 说明 |
|---|---|
| `calendar` | 倒排日历（节点/日期/动作/确认点/状态） |
| `t0_timetable` | T-0 时点表（本地时间已换算） |
| `t1_checklist` | T-1 十项清单（逐项打勾） |
| `escalation_rules` / `decision_log` | 升降级规则与决策记录 |

## 使用步骤（SOP 执行流）

1. 提供 launch_date + 时区 + 平台 → 产出日历与时点表
2. T-7 起按日历执行；T-3 口径库**逐条**确认（不许批处理默认通过）
3. T-1 清单逐项打勾——红线未过 → 触发降级规则延后 24h
4. T-0 按时点表人工发布；PH 黄金窗口（00:01-02:00 PT）不排其他动作
5. T+1/T+7 按 `battle-report-generate` 出战报与复盘

### 连接器与降级路径

- 只读优先：连接器仅用于提醒（日历订阅），发布动作一律人工在平台原生界面执行
- 第三方工具须确认 OAuth 最小权限（发布权限而非账号全权）；无法确认 → 降级手动
- 降级路径：连接器失效 → 打印时点表人工执行（本 SOP 无外部依赖也能跑）

## 边界（不做的事）

- ❌ 不自动发布、不代点发布按钮
- ❌ T-1 未全绿不建议「先发再说」
- ❌ 不用 incentivized 手段凑首发势能（互赞群/投票互换）
- ❌ 确认点不批处理——FAQ 口径必须逐条确认
- ❌ 不凭感觉改时点表（时点是数据结论，改前要给依据）

## 调用示例

**输入**（`examples/input.json`）：

```json
{
  "product": "ClipMate",
  "launch_date": "2026-09-29（周二）",
  "timezone_local": "UTC+8",
  "platforms": ["ProductHunt", "X", "Reddit", "V2EX", "即刻"],
  "waitlist_size": 812
}
```

**输出**（见 examples/output.md）：倒排日历 T-7→T+7；PH 00:01 PT 换算为本地
15:01 并设 14:30/14:50/15:01 三闹钟；T-1 十项清单（含 V2EX 账号注册时长核对）；
升降级规则预置（waitlist 阈值 1200+）。

## 所属工作流

- `publish-calendar-flow`（发布日历排期流程）
- 时间轴上的兄弟节点：T-0 值守走 `daily-comment-duty-flow`；T+1 走 `launch-battle-review-flow`

## 合规声明

- 所有对外发布动作人工确认并人工执行
- 遵守平台规则：PH 无 incentivized voting、Reddit 披露 I made this、
  微博/公众号 AIGC 标识按现行要求
- waitlist 邮件发送前人工抽查退订链接
