# 使用示例

以下示例的输入均为**真实可跑数据**，脚本输出由 `scripts/battle_report.py` 实跑产生
（Python 3.13，退出码 0）。

---

## 示例 1：四平台发布日全量战报（贴线未过 + waitlist 失守）

**输入**：见 `examples/input.json`（PH/V2EX/X/即刻 四平台 + 24 小时逐时 PV + 五指标目标）。

**输出**（实跑）：达标 1/5 —— PV 98% / 注册 91% / 星 97% 均 🟡，waitlist 6% 🔴，
提及 133% ✅。归因提示 3 条：waitlist 转化 0.2% 低于 3% 基准（钩子/表单问题）。

**模型归因示例**：流量、转化两层都正常（PV→注册 5.5%），问题锁定在 waitlist 表单
门槛；PH 占比 65% 属健康偏集中，V2EX 10 点峰与晚间 20 点峰在曲线上清晰可见。

## 示例 2：PH 掉榜型（流量层问题）

**输入**：

```json
{
  "product": "NoteSync",
  "targets": {"pv": 8000, "signups": 400},
  "platforms": [
    {"name": "ProductHunt", "pv": 850, "signups": 30, "note": "当日榜第 41，未进首页"},
    {"name": "V2EX", "pv": 620, "signups": 35, "note": "上午 10 点发"},
    {"name": "X/Twitter", "pv": 210, "signups": 9}
  ]
}
```

**输出**（实跑口径）：PV 1680 / 目标 8000 = 21% 🔴；PV→注册 4.0%（低于 5% 基准）。

**归因要点**：PH 掉榜（30 名外流量通常只有前十的 1/5-1/10）是主因；
四层漏斗定位在**流量层**——不该急着改落地页，应先诊断 PH 素材（tagline/首图/首评）
并联动 X 晚间峰补推。

## 示例 3：转化层问题（流量够、转化崩）

**输入**：

```json
{
  "product": "PDFtk Pro",
  "targets": {"pv": 3000, "signups": 300},
  "platforms": [
    {"name": "ProductHunt", "pv": 2600, "signups": 52, "note": "当日榜第 5"},
    {"name": "V2EX", "pv": 700, "signups": 14}
  ]
}
```

**输出**（实跑口径）：PV 3300 ✅ 达标（110%）；注册 66 / 300 = 22% 🔴；
PV→注册 2.0%，触发「<3% 查落地页」规则。

**归因要点**：榜第 5 说明素材没问题、流量质量没问题——问题在落地页三高发点：
首屏 5 秒讲不清 / 加载 >3 秒 / CTA 藏在第二屏以下。这是**转化层**问题，
改落地页优先于补流量。

## 示例 4：目标未设（对照组）

**输入**：

```json
{"product": "TinyPNG CLI", "platforms": [{"name": "V2EX", "pv": 400, "signups": 20}]}
```

**输出**（实跑口径）：各指标判定为「未设目标」，整体判定「未设目标」，
只输出基准对照（PV→注册 5.0% 在基准带内），不做达标结论。
